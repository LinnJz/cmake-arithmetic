# Article Writing

文章撰写不是单一动作，而是管线。判断用户处于哪个阶段、要哪种文章，读取对应 reference 执行。不要一次性加载全部 references，按需读取。

## 选择工作模式

| 用户状况 | 模式 | 读取 |
|---|---|---|
| 有想法但没结构，想先攒素材 | 素材采集 | `references/collecting.md` |
| 有素材/笔记/草稿，要论证型文章 | 论证塑形 | `references/shaping-argument.md` |
| 有素材，要叙事型/故事型文章 | 节拍叙事 | `references/narrative-beats.md` |
| 已有文章草稿，要改 | 编辑打磨 | `references/editing.md` |
| 有数据，要报告/演示/讲给利益相关者 | 数据汇报 | `references/data-storytelling.md` |

模式可组合：采集 → 塑形/节拍 → 编辑 是常见管线；数据汇报可独立用，也可作为论证塑形的原料来源。

## 通用操作纪律（所有模式生效）

- **保存路径**：用户未指定就问一次，本会话记住。
- **写入纪律**：每次写入前重读文件——用户可能编辑过；绝不盲目覆盖，只追加或就地编辑指定部分。
- **节奏**：写一块确认一块，不批量攒到最后写。
- **用户指令一等公民**："删掉上一个""这句再精炼""把这两条合并"——就地处理，不动其余部分。
- **素材是采石场，不是剧本**：可拆分、合并、改写、转述、重排素材以适配上下文；文章必须是一个声音。
- **缺口要明说**："这里缺个例子而素材里没有——现在补一个，或删掉这一段。"
- **不写超出素材范围的新内容**（素材不完整就点出缺口，由用户补齐或删段）。

- `references/editing.md` — 按信息依赖重排结构、收紧文风的编辑
- `references/data-storytelling.md` — 数据驱动叙事框架、可视化与汇报模板
