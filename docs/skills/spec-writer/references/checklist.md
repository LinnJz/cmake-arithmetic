# SPEC 自检清单

输出 SPEC 前逐项检查。任一 ❌ 都就地修复后再交付。自检结果不作为最终文档的独立章节展示，只用它来补齐 SPEC。

## 一、溯源完整性（无孤儿）

- [ ] 每条契约都能 trace 回 PRD 需求号（需求-约束映射表无空白行）
- [ ] 每个 Requirement 标注了依赖的 ADR（无约束的也要显式写"无 ADR 约束"）
- [ ] 复用领域词汇表术语，无自造同义词
- [ ] 无对应 PRD 需求的"孤儿条目"——要么补需求，要么删条目

## 二、职责边界（无重复）

- [ ] 未重述 PRD 的痛点、业务价值、功能列表
- [ ] 未抄写 ADR 的上下文、替代方案、撤销条件、权衡理由
- [ ] 行为契约未泄漏实现细节（库/类/函数/文件路径）
- [ ] 无 PLANNING 内容（里程碑、排期、资源分配）混入 SPEC——那些归 PLAN

## 三、可验证性（可写断言）

- [ ] 每个行为契约至少映射一条 AC，AC ID 连续无跳号
- [ ] 每条 AC 的期望结果是确定性通过/失败，无"工作正常/符合预期"式模糊表述
- [ ] 错误矩阵覆盖七类场景：空数据 / 超时 / 并发 / 重复 / 超长非法输入 / 下游不可用 / 权限
- [ ] 每个错误码在接口契约与错误矩阵中一致，无同码异义
- [ ] Good / Base / Bad 至少一组，且 Bad 含 Wrong vs Correct 反例

## 四、完整性（状态与迁移）

- [ ] 有状态组件状态机完整：每个状态有进入/退出条件，无悬空状态；无状态组件显式声明"无状态"
- [ ] 数据契约含字段表（类型/可空/索引）；变更表写明迁移影响
- [ ] 接口契约含 Request/Response/Errors 三要素与兼容性标注

## 五、可估时（喂养 PLAN）

- [ ] WBS 输入表已填：接口数 / 表实体数 / 状态数 / AC 数 / 迁移项 / 估算建议
- [ ] Open Questions 已登记，需新架构决策的已标注"回流 adr-writer"

## 六、文档卫生

- [ ] 无"待定 / TBD / 视情况而定 / 后续补充"占位符
- [ ] 全文术语统一，首次出现有定义
- [ ] 变更历史已记录
