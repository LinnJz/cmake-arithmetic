# ADR 模板

ADR 存储在 `docs/adr/NNNN-{slug}.md`。**五要素（背景/决策/后果/替代方案/撤销条件）不可省略**；其余部分按价值取舍。重大决策用完整版，轻量决策用单段式。

## 完整模板

```markdown
# ADR-{编号}：{标题}

- **状态**： [Proposed | Accepted | Deprecated | Superseded]
- **日期**： {YYYY-MM-DD}
- **作者**： {姓名/团队}
- **最后修改**： {YYYY-MM-DD}

## 上下文
描述当前面临的技术问题、业务约束和背景环境。
包括：团队规模、技术栈版本、性能要求、时间压力等。

## 决策
我们决定采用{方案X}。具体来说：
- 选用了具体的组件/版本
- 使用的具体方式
- 不做的范围界定

## 后果
正面：
- {正面影响1}
- {正面影响2}

负面：
- {负面影响1}
- {负面影响2}

## 替代方案
方案A：{描述}。不选原因：{原因}
方案B：{描述}。不选原因：{原因}

## 撤销条件
当以下条件出现时，应重新评估此决策：
- {条件1}
- {条件2}

## 关联ADR
- **Supersedes**：ADR-XXX（本决策取代…）
- **Depends on**：ADR-XXX（…是使用…的前提）
- **Refines**：ADR-XXX（本决策细化了…）
- **Related to**：ADR-XXX（与…同领域，无直接依赖）

## 变更历史
| 日期 | 变更类型 | 原因 | 操作人 |
|------|---------|------|--------|
| {YYYY-MM-DD} | 创建 | 首次编写 | {姓名} |
```

## 单段式（轻量决策）

仍须隐含覆盖五要素实质——一段话里讲清背景、决定、后果、被否的替代、何时重选：

```markdown
# {标题}

{1-3 句话：上下文是什么、我们决定了什么、为什么这么选。必须覆盖五要素：背景/决策/后果/替代方案/撤销条件。}
```

## 写作规则

- **后果**：至少 2 个正面 + 2 个负面/中性（完整模板已内置；单段式至少各 1 个）。
- **替代方案**：每个候选至少 1 个优点 + 1 个缺点 + 不选的具体原因。
- **撤销条件**：写成可判定的条件（"当…时，应重新评估此决策"），而非模糊描述。
- **双向引用**：若本 ADR Supersedes 某旧 ADR，在旧 ADR 末尾补"被取代：本决策已被 ADR-XXX 取代"。
- **编号**：扫描 `docs/adr/` 中最高编号 +1（用 `scripts/new-adr.ps1` 自动完成）。
