# 验证链（Verify Chain）Skill

## 这是什么

一个使用 "角色对抗 + 上下文隔离 + 联网交叉验证" 机制的**通用事实核查工具链**。

它不止用于技术文章。任何"**可以从权威来源查证的内容**"都可以验证：API 文档、PRD、科普/健康/财经内容、面试题库、工具手册、代码示例、翻译稿、合规文档……

运行验证链：
1. AI 提取内容中的关键断言
2. 多个独立 AI 实例并行联网核查每个断言
3. 发现问题自动修复

**一切以权威官方证据为准**（官方文档、政府/监管机构、期刊、标准、原始数据），而不是模型记忆。

## 快速开始

### 触发

```
/verify-chain
```
或直接说 "帮我验证这篇文章" / "核查一下内容有没有错误" / "验证这份 PRD" / "查查这个面试题答案" / "这段代码能跑吗" / "核实这个数据"……

### 领域

运行时会自动判断内容所属领域（或你说 "用 XX 领域标准验证"）。当前内置 11 个领域：

| 领域 | 验证对象 | 权威来源示例 |
|------|---------|-------------|
| `tech-article` | IT 技术文章 | 官方文档、GitHub 源码、RFC |
| `api-doc` | API/库文档 | 官方 docs、changelog、源码 |
| `product-spec` | PRD/规格 | 需求文档、issue、代码实现 |
| `sci-pop` | 科普/知识性内容 | 学术论文、权威机构 |
| `health-medical` | 健康/医疗 | 官方卫生机构、同行评审期刊 |
| `finance-econ` | 财经/经济数据 | 官方统计局、央行、权威媒体 |
| `exam-qna` | 面试/考试题库 | 官方题解、标准答案 |
| `tool-doc` | 工具使用文档 | 官方 man page、--help 实测 |
| `code-example` | 代码示例 | 实测编译/执行 |
| `translation` | 翻译稿 | 原文对照 + 领域权威源 |
| `compliance` | 合规/安全 | 官方法规库、CVE 库 |

各领域配置见 `domains/` 目录。

### 模式

| 模式 | 命令 | 说明 |
|------|------|------|
| 全自动 | `/verify-chain` | 提取 → 核查 → 修复 → 报告，一气呵成 |
| 先审再改 | "先审再改，验证文章" | 核查完成后暂停，等你审核再决定修什么 |
| 只查不改 | "只查不改，验证文章" | 只输出核查报告，不修改内容 |
| 重点检查 | "重点检查命令参数，验证文章" | 将关注点传递给 Critic |

## 它不能做什么

- 验证个人观点或主观评价（"我认为 xxx 最优" 这种）
- 验证纯原创理论（没有公开资料可对照）
- 验证无公开资料的私有系统细节
- 替代专业领域专家的深度审稿
- 100% 消除所有错误（AI 本身也有局限）

## 文件结构

```
verify-chain/
├── SKILL.md              # 入口 + 流程编排
├── README.md             # 使用说明
├── prompts/
│   ├── critic.md         # 通用 Critic 系统提示词
│   ├── verifier.md       # 通用 Verifier 系统提示词
│   └── repairer.md       # 通用 Repairer 系统提示词
└── domains/
    ├── _template.md      # 新领域配置模板
    ├── ...（11 个领域配置）
```

## 扩展新领域

复制 `domains/_template.md` 为 `domains/你的领域.md`，填写：
1. 验证对象与断言分类
2. 权威来源白名单（最重要的部分）
3. 禁止引用列表
4. 搜索偏好
5. 修复策略

然后按 SKILL.md 的"领域选择"自动判定规则或让用户手动指定即可。
