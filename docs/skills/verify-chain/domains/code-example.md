# 领域配置：代码示例（可执行代码）

## 验证对象

示例代码能否编译/运行、输出是否正确、API 用法是否合法、依赖是否完整、跨版本行为。

## 触发示例

- "这段代码能跑吗" / "验证这个代码示例"
- "教程里的代码有没有编译错误"

## 断言分类体系

| 类别 | 说明 | 示例问题 |
|------|------|---------|
| `Compile` | 代码能否通过编译/语法检查 | "这段 Rust 代码能通过 borrow checker 吗？" |
| `Runtime` | 运行时是否报错、输出是否符合预期 | "该循环会不会死循环？" |
| `APIUse` | API 用法是否合法、签名是否匹配 | "`map()` 的回调签名是否写对？" |
| `Semantics` | 代码语义与文字描述是否一致 | "代码实现的是文中说的 '深拷贝' 吗？" |
| `EnvDep` | 依赖、版本、环境前提是否完整 | "示例遗漏了哪些 import？" |
| `Bug` | 隐含 bug：边界、并发、空指针、资源泄漏 | "该示例是否泄漏了文件句柄？" |

## 权威来源白名单（按优先级）

1. **实测编译/运行**（优先本地或 Compiler Explorer 实测）
2. 官方文档示例与官方仓库测试用例
3. 语言规范/类型定义
4. 高票社区解答 —— 交叉参考

## 绝对禁止引用

- 无法运行验证的纯转述
- 未标注版本的旧 API 用法示例

## 搜索偏好

- **语言**：跟随代码注释/文档语言
- **时效**：标注目标语言/框架版本
- **关键词策略**：不依赖搜索，**以实测为主**

## 修复策略备注

- 所有结论尽量附实测结果（编译输出 / 运行输出）
- 修复后给出可运行的完整示例（补全 import、依赖）
- 实测不可得时标 ❓ 并说明缺什么环境
