# Adapting cmake-build to Your Environment

This skill is preset-first. For projects generated by the cmake-arithmetic template, local paths should be captured in `CMakeUserPresets.json`, then builds should run through `cmake --preset`, `cmake --build --preset`, and `cmake --install`.

Use `scripts/detect-env.ps1` only when presets are missing, local SDK paths are broken, or you are diagnosing a hand-written CMake project.

## Architecture: How paths flow

```
User says "build project"
         │
         ▼
  cmake --list-presets all -S .
    │
    ├── visible preset exists ───────► cmake --preset "<name>"
    │                                  cmake --build --preset "build-<name>"
    │
    └── no presets / broken paths ───► scripts/detect-env.ps1 ──► JSON output
    │
    ├── ① Environment variables    (VCPKG_ROOT, QTDIR)
    ├── ② Cache file              ($USERPROFILE\.cmake-build\cache.json)
    ├── ③ Auto-detection          (vswhere, registry, common paths)
    └── → If all null → agent invokes resolve flow
                           │
             ┌─────────────┴─────────────┐
             │                           │
        User sets env var          User provides path
             │                           │
             │                     Agent writes to cache
             │                     (& "detect-env.ps1" -CacheQtSdkDir "...")
             └─────────────┬─────────────┘
                           ▼
                  Next run finds path
                  from env / cache
```

**Key insight**: Only two things are hard to auto-detect:
- **vcpkg root** (no standard registry key)
- **Qt SDK dir** (no `QTDIR` env var by default)

Everything else (MSVC, Ninja, VS) is found automatically via `vswhere` and `PATH`. In generated projects, vcpkg and Qt paths should normally be written into `CMakeUserPresets.json` by `generate.py`.

## Three configuration methods (pick one)

### Method A: Generate user presets from TOML (recommended for this template)

Set local values in `project.toml`, then regenerate the project:

```toml
[vcpkg]
root = "D:/tools/vcpkg"
static_triplet = "x64-windows-static-md"
dynamic_triplet = "x64-windows"

[qt]
enabled = true
sdk_dir = "D:/Qt/6.6.2/msvc2019_64"
compiler = "msvc"
```

```powershell
python generate.py
cmake --list-presets all -S <generated-project>
Push-Location <generated-project>
cmake --preset "qt_msvc_x64_debug"
cmake --build --preset "build-qt_msvc_x64_debug"
cmake --install "out/build/qt_msvc_x64_debug"
Pop-Location
```

Generated projects keep development outputs in `out/build/<preset>/artifacts`
and install clean runtime/import artifacts to `out/install/<preset-group>`.
For example, `qt_msvc_x64_debug` installs to
`out/install/qt_msvc_x64/debug/bin` and `out/install/qt_msvc_x64/debug/lib`.

### Method B: Set environment variables

Set these **before** running the skill. The skill checks them first, no cache needed.

```powershell
# vcpkg root
$env:VCPKG_ROOT = "D:/tools/vcpkg"

# Qt SDK dir (the directory containing bin/, lib/, include/)
$env:QTDIR = "D:/Qt/6.6.2/msvc2019_64"

# Optional: triplets (skill provides sensible defaults)
$env:VCPKG_STATIC_TRIPLET  = "x64-windows-static-md"
$env:VCPKG_DYNAMIC_TRIPLET = "x64-windows"
```

To make permanent, add to your PowerShell profile:
```powershell
Add-Content -Path $PROFILE -Value @"
`$env:VCPKG_ROOT = "D:/tools/vcpkg"
`$env:QTDIR = "D:/Qt/6.6.2/msvc2019_64"
"@
```

### Method C: Let agent cache your path during first manual fallback

Just ask the agent to build. If no usable presets exist and detection fails, it will ask for the path.
Once you provide it, the agent runs `detect-env.ps1 -CacheQtSdkDir "..."` to persist it.

```
You:  build the project
Agent: I found MSVC and vcpkg, but Qt SDK was not auto-detected.
       Please provide your Qt installation path:
       (e.g. C:/Qt/6.6.2/msvc2019_64)
You:  D:/Qt/6.6.2/msvc2019_64
Agent: ✓ Path cached. Running build...
```

Next time you run `build`, the cache is found automatically — no prompting needed.

### Method D: Pre-populate cache manually

```powershell
& "scripts/detect-env.ps1" -CacheVcpkgRoot "D:/tools/vcpkg"
& "scripts/detect-env.ps1" -CacheQtSdkDir "D:/Qt/6.6.2/msvc2019_64"
```

Methods C and D write to the same cache file. Env vars still take priority over cache.

## Cache file reference

| Item | Value |
|------|-------|
| File location | `$env:USERPROFILE\.cmake-build\cache.json` |
| Persistence | Across all projects and sessions |
| Clear | Delete this file to force re-detection |
| Priority | env vars > cache > auto-detect |

## Verification checklist

After configuration, verify the skill works:

```powershell
# 1. Prefer preset visibility
cmake --list-presets all -S .

# 2. If presets are missing or local paths fail, run detection script
& "scripts/detect-env.ps1"

# 3. Check that msvc.cl_path is found
#     → If null, vswhere might need the VS Installer workload

# 4. Check that vcpkg.root is found
#     → If null, set $env:VCPKG_ROOT

# 5. Check that qt.sdk_dir is found
#     → If null, set $env:QTDIR or install Qt

# 6. Check that generator is not "NMake Makefiles"
#     → Install Ninja: winget install Ninja-build.Ninja
```

## What if something is missing?

| Missing | Detection method | Fix |
|---------|-----------------|-----|
| MSVC/cl.exe | vswhere + fallback paths | Install "Desktop development with C++" workload in VS Installer |
| vcpkg | `VCPKG_ROOT` env > hardcoded paths | `git clone https://github.com/microsoft/vcpkg` then set `$env:VCPKG_ROOT` |
| Qt | `QTDIR` env > registry | Set `$env:QTDIR` to your Qt SDK directory |
| Ninja | `PATH` | `winget install Ninja-build.Ninja` or `pip install ninja` |

## Portability summary

| Component | Auto-detects? | Works on other machines? |
|-----------|--------------|--------------------------|
| MSVC/cl.exe | ✅ vswhere | ✅ Any VS 2017–2022 install |
| Ninja | ✅ PATH check | ✅ If installed and on PATH |
| CMakePresets | ✅ File exists check | ✅ Project-specific |
| vcpkg | ✅ by env var, ⚠️ fallback paths | ✅ if env var set; fallback paths are generic |
| Qt | ✅ by env var or registry | ✅ if env var set or Qt installed normally |
| vcpkg triplet | ⚠️ hardcoded default | ✅ Usually correct; override via env var |
