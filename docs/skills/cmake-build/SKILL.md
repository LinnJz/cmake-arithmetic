# CMake Build

## Core Rule

Use presets first. For projects generated by the cmake-arithmetic template,
`CMakePresets.json` contains shareable hidden bases and `CMakeUserPresets.json`
contains local visible configure/build/test presets. Do not hand-assemble
`cmake -B ... -D...` commands when a matching visible preset exists.

## Preset Workflow

Always run these steps from the project root.

### 1. Inspect Presets

```powershell
cmake --list-presets all -S .
```

If this succeeds, choose a visible configure preset and prefer the matching
build preset.

Generated preset names follow this convention:

| Mode | Configure preset | Build preset |
|------|------------------|--------------|
| Non-Qt MSVC Debug | `msvc_x64_debug` | `build-msvc_x64_debug` |
| Non-Qt Clang Release | `clang_x64_release` | `build-clang_x64_release` |
| Non-Qt GCC RelWithDebInfo | `gcc_x64_relwithdebinfo` | `build-gcc_x64_relwithdebinfo` |
| Qt MSVC Debug | `qt_msvc_x64_debug` | `build-qt_msvc_x64_debug` |
| Qt MSVC Release | `qt_msvc_x64_release` | `build-qt_msvc_x64_release` |

Use the exact names reported by `cmake --list-presets all`; do not invent names.

### 2. Select Preset

Infer build type from the user request:

| User intent | Build type suffix |
|-------------|-------------------|
| debug, default build, 构建, 调试 | `debug` |
| release, 发布 | `release` |
| release with debug info, 带调试信息发布 | `relwithdebinfo` |

Infer mode from available presets:

- If the user asks for Qt, choose a `qt_*` preset.
- If only non-Qt presets exist, choose non-Qt presets.
- If both Qt and non-Qt presets exist and the user did not say which one, prefer
  non-Qt for CLI/library projects and Qt for projects that use Qt targets or
  `QT_SUPPORT=ON`.
- If the user names a compiler, choose that compiler. Otherwise prefer `msvc`
  on Windows because the template's vcpkg/Qt defaults are MSVC-oriented.

### 3. Configure

```powershell
cmake --preset "<configure-preset>"
```

Examples:

```powershell
cmake --preset "msvc_x64_debug"
cmake --preset "qt_msvc_x64_debug"
```

Qt presets should supply `QTDIR` and `QT_SDK_DIR` through
`CMakeUserPresets.json`. vcpkg paths and triplets should also come from
`CMakeUserPresets.json` cache variables when configured.

### 4. Build

Prefer build presets when they exist:

```powershell
cmake --build --preset "<build-preset>"
```

Example:

```powershell
cmake --build --preset "build-msvc_x64_debug"
```

If no build preset exists, build the configure preset's binary directory:

```powershell
cmake --build "out/build/<configure-preset>" --parallel 8
```

Only use `--config <Debug|Release|RelWithDebInfo>` for multi-config generators
such as Visual Studio. The template defaults to Ninja single-config presets, so
`CMAKE_BUILD_TYPE` is set during configure.

### 5. Test

If test presets exist:

```powershell
ctest --preset "<test-preset>"
```

If no test preset exists, use the configured build directory:

```powershell
ctest --test-dir "out/build/<configure-preset>" --output-on-failure
```

### 6. Install

Use the configured build directory. The generated framework keeps intermediate
build outputs in `out/build/<configure-preset>` and installs clean deploy/import
artifacts under `out/install/<preset-group>`.

```powershell
cmake --install "out/build/<configure-preset>"
```

Examples:

```powershell
cmake --install "out/build/msvc_x64_debug"
cmake --install "out/build/qt_msvc_x64_debug"
```

Generated install layout follows this convention:

| Build type | Runtime | Libraries/import libraries |
|------------|---------|----------------------------|
| Release | `out/install/<preset-group>/bin` | `out/install/<preset-group>/lib` |
| Debug | `out/install/<preset-group>/debug/bin` | `out/install/<preset-group>/debug/lib` |
| RelWithDebInfo | `out/install/<preset-group>/relwithdebinfo/bin` | `out/install/<preset-group>/relwithdebinfo/lib` |

`<preset-group>` is the configure preset without the build-type suffix, for
example `msvc_x64` or `qt_msvc_x64`.

## When Presets Are Missing

If neither `CMakePresets.json` nor `CMakeUserPresets.json` exists:

1. Check for `project.toml` and `generate.py`.
2. If present, generate a project first instead of configuring the template
   directory directly:

   ```powershell
   python generate.py
   ```

3. Build the generated project directory with the preset workflow above.
4. If this is a normal hand-written CMake project with no generator, fall back
   to manual configure.

Manual fallback:

```powershell
cmake -S . -B out/build/manual-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build out/build/manual-debug --parallel 8
```

Use `scripts/detect-env.ps1` from this skill only for manual fallback or for
diagnosing missing local SDK/tool paths. The generated framework should normally
receive local Qt/vcpkg settings through `CMakeUserPresets.json`.

## Generated Framework Contract

The cmake-arithmetic generator splits responsibility as follows:

| File | Responsibility |
|------|----------------|
| `project.toml` | Source configuration for project metadata, Qt mode, vcpkg, dependencies, and preset shape |
| `CMakePresets.json` | Shareable hidden bases: `base`, `non-qt-base`, `qt-base`, and compiler bases |
| `CMakeUserPresets.json` | Local visible configure/build/test presets with SDK paths and architecture/toolset |
| `CMakeLists.txt` | Project structure, Qt enablement, C++ standard, build-tree artifact directories, and helper module imports |
| `<subproject>/Dependencies.cmake` | Generated dependency intent: packages, links, definitions, and copied DLLs |

Do not put machine-specific Qt SDK paths or vcpkg roots into
`CMakePresets.json`. They belong in `CMakeUserPresets.json` or environment
variables consumed by user presets.

Generated projects should not write build outputs into a source-root `bin/`
directory. Treat `out/build/<preset>/artifacts` as developer-only output and
`out/install/<preset-group>` as the clean layout to run, deploy, or consume.

## Qt Rules

- Qt mode is selected by `[qt].enabled = true` or a configured `[qt].sdk_dir`
  in `project.toml`.
- Qt configure presets are named `qt_<compiler>_<arch>_<build-type>`.
- Qt local presets must provide `QTDIR` and `QT_SDK_DIR`.
- Do not add `-DCMAKE_PREFIX_PATH=<qt>` manually if a Qt preset is available;
  `qt-base` uses `$env{QTDIR}`.
- For Qt Debug presets, `QT_QML_DEBUG` and `QML_DEBUG_ARGS` may be present.

## Non-Qt Rules

- Non-Qt configure presets are named `<compiler>_<arch>_<build-type>`.
- Default Windows compiler preference is `msvc`, then `clang-cl`, then
  `clang`, then `gcc`, unless the user requested one.
- Non-Qt presets set `QT_SUPPORT=OFF`; do not pass Qt paths manually.

## Error Handling

When configure or build fails:

1. Capture the failing command and the first real CMake/compiler error.
2. Re-run with the exact same preset and `--verbose` only if link/compile
   command details are needed.
3. For missing packages, inspect generated `<subproject>/Dependencies.cmake`
   and vcpkg triplet cache variables.
4. For missing Qt components, inspect `QTDIR`, `QT_SDK_DIR`, and the Qt preset.
5. For runtime mismatch, check `MSVC_RUNTIME_MODE`,
   `VCPKG_STATIC_TRIPLET`, and `VCPKG_DYNAMIC_TRIPLET`.

See [references/build-reference.md](references/build-reference.md) for detailed
compiler, runtime, dependency, and error tables.
