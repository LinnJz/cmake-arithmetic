# 四文档接口契约

链条上每份文档向"下游"传递的物、消费方与完整性校验。se-workflow 路由时据此判断"输入是否齐备"——缺口即下一步。

## 链条总览（递进）

```
PRD(业务) ──需求清单/范围冻结──→ ADR(架构) ──决策约束──→ SPEC(实现契约) ──WBS输入+AC──→ PLAN(管理节奏)
     ↑__________________________ 反向约束 __________________________|
```

## 接口契约表

| 契约 | 传递物 | 消费方 | 完整性校验 |
|------|--------|--------|-----------|
| PRD→ADR | 范围冻结项（目标用户/核心功能/平台/页面/不做清单）、需求背景 | adr-writer 评估可行性、识别决策点 | 范围冻结已确认；功能列表带优先级 |
| ADR→SPEC | 决策约束（选型落地形态、不做范围、撤销条件） | spec-writer 投影为契约字段/形态 | ADR 状态 Accepted；五要素齐全 |
| SPEC→PLAN | WBS 输入表（接口数/表数/状态数/AC 数/迁移项/估算建议）、AC 验证锚点 | plan-writer 拆任务、排期、定 Gate | SPEC 自检通过（无孤儿/无重复/可验证） |
| PLAN→执行 | 阶段表（S0-S7 + Gate 判据）、coding-checklist、风险缓冲、回流规则 | 实施/测试/验证/质量门 | 计划评审通过；每任务有验证锚点 |

## 回流传播路径（反馈闭环）

| 触发器 | 先改 | 再改 | 最后回归 |
|--------|------|------|----------|
| 测试失败（P0/P1） | 实施修正 | — | 回归测试（S5） |
| 验证不通过（AC 红） | SPEC（契约错时）或实施（实现偏时） | 同步 AC | 重验（S6） |
| 排期超限 | PRD（砍需求） | SPEC（删对应契约） | 重排（PLAN） |
| SPEC 发现 ADR 撑不住 | ADR（新建/取代） | SPEC（更新依赖） | 回归 S3/S4 |
| Code Review 架构级问题 | ADR（新增） | SPEC/PLAN 受影响任务 | 重新推进 |
| 外部依赖延期 | PLAN 里程碑/缓冲 | 若超限走"排期超限"路径 | 重排 |

规则：**任何回流先更新受影响的上游文档，再回归执行**，禁止带伤硬扛。

## 单份文档跳入（链条支持任意起点）

| 用户只点名 | 处理 |
|-----------|------|
| PRD | 独立执行，不强制走全链 |
| ADR | 独立执行；若因 PRD 需求而生，登记关联需求号 |
| SPEC | 无 PRD/ADR 时提示缺口（"建议先补 PRD/ADR，或明确这只是参考性规格"），由用户决定 |
| PLAN | 无 SPEC 时提示先出 WBS 输入（plan-writer 的起点推断会校验），否则计划无源 |

## 编排时的输入交接

se-workflow 把控制权转交给文档 skill 时，必须附带该 skill 需要的输入，不空转调用：

| 转交目标 | 附带输入 |
|----------|----------|
| prd-writer | 用户原始诉求（若已有概念 PRD 则带上） |
| adr-writer | PRD 范围冻结项、候选方案、约束 |
| spec-writer | PRD 需求清单 + 相关 ADR 约束 |
| plan-writer | SPEC 的 WBS 输入表 + AC 表 |
