# 软件工程工作流（se-workflow）

## 定位（边界）

se-workflow 是 PRD（为什么做）、ADR（怎么做）、SPEC（具体长什么样）、PLAN（什么时候交付）四文档工作流的**入口编排器**。它拥有三样东西：

- **路由**：什么场景该用哪个 skill。
- **接口契约**：文档间传递什么物（见 `references/chain-contracts.md`）。
- **回流传播**：反馈闭环往哪走、先改哪份文档。

它不拥有：任何单份文档的写法、自检、红线——那些属于 prd-writer / adr-writer / spec-writer / plan-writer。**本 skill 不重复任何文档 skill 的内容，只引用。

## 核心模型：链条与回流

递进（由虚到实，不可跳级）：

```
PRD(业务) → ADR(架构) → SPEC(实现契约) → PLAN(管理节奏)
   ↑______________________ 反向约束 ______________________|
```

两条回流（先更新上游文档，再回归执行）：
- **PLAN 反推 PRD**：排期超限 → 砍需求 → 更新 PRD → 同步 SPEC → 重排。
- **SPEC 反推 ADR**：规格写不下去 / 并发撑不住 → 新建 ADR → 更新 SPEC → 回归。

## 路由表（核心）

| 用户意图 | 路由到 | 触发词示例 |
|----------|--------|-----------|
| 新项目/新功能端到端        | 本 skill 编排 → 依次路由           | "启动一个项目/功能""走完整流程" |
| 点名单份文档 | 对应 skill（本 skill 静默） | "写一份 PRD/ADR/SPEC/PLAN" |
| 需求讨论/概念验证/MVP 范围 | prd-writer | "产品想法""功能需求""MVP" |
| 技术选型/架构决策 | adr-writer | "选什么技术""为什么用 X 不用 Y" |
| 接口/数据/详细规格 | spec-writer | "接口怎么定义""数据表怎么设计" |
| 排期/里程碑/阶段计划 | plan-writer | "什么时候交付""拆任务排期" |
| 流程进度/下一步            | 本 skill（扫描已有产物推断）       | "到哪一步了""下一步该做什么"    |
| 跨文档问题回流             | 本 skill 判传播路径 → 转对应 skill | "ADR 撑不住""排期超了""AC 红了" |

## 冲突消解规则（语义同时命中多个 skill 时）

| 用户表述 | 裁决 |
|----------|------|
| "写一份 SPEC" | spec-writer（文档被点名，本 skill 静默） |
| "按流程写 PRD" | prd-writer 直接执行（本 skill 不抢） |
| "启动这个项目，帮我走完整流程"  | 本 skill 编排 → 路由到 prd-writer        |
| "现在到哪一步了 / 下一步写什么" | 本 skill |
| 执行中"ADR 撑不住 / 排期超了" | 本 skill 判回流路径 → 转对应 skill |

裁决优先级：**点名单份文档 > 链条级意图 > 回流**。

## 编排流程（被加载后执行）

1. **识别起点**：扫描仓库已有 PRD/ADR/SPEC/PLAN 产物，推断链条进度与缺口。
2. **确定缺口**：链条中缺哪份文档/哪个阶段 → 即下一步。
3. **路由并转交**：显式声明"现在调用 {skill 名}"，并附带该 skill 需要的输入（见 `references/chain-contracts.md` 的输入交接表）。
4. **登记回流**：执行中触发回流时，先更新受影响文档，再回归。
5. **推进检查**：每个 Gate 后更新进度记录（可引导使用 plan-writer 的 progress.md 机制）。

## 红线

- 不撰写任何单份文档——连初稿都不代写，只路由。
- 不重复文档 skill 的定位/自检/红线内容，只引用。
- 不跳级：SPEC 未就绪不路由到 plan-writer；PRD 未冻结不路由到 spec-writer。
- 收到"点名单份文档"的请求时让位给对应 skill，不抢占。
- 回流时不做"带伤回归"——先改上游文档再继续。

## 底线

**se-workflow 是四文档链条的路由器，不是作者。** 它保证"谁该上场、输入是什么、反馈往哪走"，写作质量交给四个专职 skill。触发可靠性靠 description 互斥设计，并通过 `references/trigger-tests.md` 的场景持续实测校准。
