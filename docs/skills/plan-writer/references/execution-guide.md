# S4 实施：子代理执行指南

主代理负责协调与决策，所有实现交给子代理执行。保持主代理上下文用于全局判断。

## 上下文保护原则

- 主代理：协调、分派、核对证据、决策。
- 子代理：所有代码编写、编辑、实现工作，无论任务大小。
- 禁止主代理亲自实现——即使"一行小改动"，也分派子代理。读取文件核对可以，编辑不行。

## 分派策略

| 任务形态 | 分派方式 |
|----------|----------|
| 单任务 | 1 个子代理 |
| 独立多任务 | 并行子代理（每任务一个） |
| 依赖任务 | 串行子代理（每个只传它需要的上游摘要） |

## 最小上下文

只给子代理任务局部切片：任务文本、允许修改的文件、验证锚点、必需的直接上游摘要。不传无关上下文。

## 模型分层

- 默认用轻量子代理执行；主代理保留高配模型做协调。
- 子代理失败或需深度推理时，升级到主模型重试。
- 升级后仍失败 → 停下报告用户，不硬扛。

## 执行循环

1. 读计划，批判性复核；有疑问先与用户对齐，不盲目执行。
2. 按依赖关系分派子代理（见分派策略）。
3. 子代理严格按计划的 bite-size 步骤执行，运行验证。
4. 主代理独立核对子代理输出（见 gates-and-loops.md 证据先于断言）——不信任口头"已通过"。
5. 用 TodoWrite 标记 in_progress / completed。

## 停止信号

遇到下列情况立即停下问用户，不猜测：
- 阻塞（依赖缺失 / 测试失败 / 指令不明）
- 计划存在无法启动的关键缺口
- 验证反复失败
- 需要回退早期步骤时

## 推进衔接

- 每批完成 → 独立核对证据 → 满足 Gate 才切换阶段。
- 批量完成后更新 handoff.md。
- 全部完成后进入 S7 质量门（code-review），再按 finishing-guide.md 收尾。
- 禁止在主线分支直接实施（除非用户明确同意）。
