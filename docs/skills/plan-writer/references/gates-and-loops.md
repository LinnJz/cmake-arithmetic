# Gate 判据与回流细则

阶段推进与反馈回流的具体判据。执行任何阶段退出声明前阅读。

## 一、Gate 判据：证据先于断言（Iron Law）

**任何阶段退出声明 = 声明"阶段完成"，必须附当次运行的验证证据。**

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

退出声明流程（跳过任何一步 = 未验证）：
1. **IDENTIFY**：什么命令/检查能证明该 Gate 通过？
2. **RUN**：完整运行（当次，不许用之前的结果）。
3. **READ**：读取完整输出，检查退出码，统计失败数。
4. **VERIFY**：输出是否确认声明？否 → 如实报告现状；是 → 附证据再声明。

各阶段 Gate 的证据要求：

| 阶段 | 退出证据（缺一不可） |
|------|------------------------|
| S0 计划编制 | 计划与 PRD/ADR/SPEC 的逐项核对记录 |
| S1 需求 | PRD 评审结论 + 范围冻结确认 |
| S2 架构 | ADR 评审结论 |
| S3 规格 | spec-writer 自检清单全过（无孤儿/无重复/可验证） |
| S4 实施 | 每任务验证锚点运行输出（测试命令 + 结果） |
| S5 测试 | 测试命令输出：0 失败 |
| S6 验证/验收 | AC 逐条勾选表，全绿 |
| S7 质量门 | Code Review 结论：无 Critical/Important 遗留 |

各阶段执行细则：S4 按 `execution-guide.md`，S5 按 `tdd-guide.md`，S6 按 `acceptance-testing.md`，收尾按 `finishing-guide.md`。

**禁止的退出声明**：用"应该/大概/看起来没问题"；用先前运行结果替代当次；信任子代理/他人"已通过"的口头报告（要独立核对输出）。

## 二、阶段推进由产出物触发

阶段切换不是口头说"做完了"，而是产出物就位 + 证据齐全。参考 artifact 触发约定：

| 阶段 | 触发推进的产出物 |
|------|------------------|
| S1→S2 | PRD 冻结 |
| S2→S3 | ADR 评审通过 |
| S3→S4 | SPEC 自检通过 + WBS 输入齐 |
| S4→S5 | 产出物可测（测试锚点就位） |
| S5→S6 | 测试 0 失败 |
| S6→S7 | AC 全绿 |
| S7→Done | 质量门无遗留 |

## 三、测试 vs 验证（分工明确）

| | 测试（S5） | 验证/验收（S6） |
|---|---|---|
| 目的 | 找错——暴露缺陷 | 确认——对照 SPEC 契约与 AC 打勾 |
| 主体 | 开发自证 | 独立验收（可换人/评审） |
| 依据 | 验证锚点、AC | SPEC 契约 + AC 全表 |
| 失败处理 | 修正 → 回归 | 回 SPEC 澄清契约 或 回实施 |

## 四、回流触发器（持续迭代）

每个触发器都必须**先更新受影响的上游文档，再回归执行**，禁止带伤硬扛。

### 1. 测试失败（P0/P1）
- 动作：回 S4/S5 修正 → 回归测试 → 重新走 S5 Gate。
- 禁止：声称"改好了"而不重新运行测试（回归必须当次重跑）。

### 2. 验证不通过（AC 红）
- 判断：是契约写错，还是实现偏离契约？
  - 契约错 → 回 S3 修订 SPEC → 同步 AC → 重验。
  - 实现偏 → 回 S4 修正 → 重测 → 重验。

### 3. 排期估算超限（PLAN 反推 PRD）
- 动作：列出可砍项（P1/P2）→ 与用户确认砍需求 → 更新 PRD 范围 → 同步 SPEC → 重新排期。
- 禁止：不加缓冲硬排，或悄悄缩水验收标准。

### 4. SPEC 发现 ADR 撑不住（SPEC 反推 ADR）
- 动作：登记开放问题 → 用 adr-writer 新建 ADR → 更新 SPEC 依赖 → 回归 S3/S4。
- 禁止：在 PLAN 里临时改架构决策而不留记录——架构变更必须走 ADR。

### 5. Code Review 发现架构级问题
- 动作：回 S2 重估 → 新增 ADR → 更新 SPEC/PLAN 受影响任务 → 重新推进。
- Critical/Important 未解决不得进入下一步。

### 6. 外部依赖延期
- 动作：更新里程碑日期与缓冲 → 若影响排期超限，转触发器 3。

## 五、止损与重估

- 连续两轮同阶段回流仍未通过 → 停下向用户报告，不硬扛。
- 重估触发条件：缓冲耗尽 / 外部依赖延期超阈值 / 范围蔓延。
- 重估输出：更新版计划（阶段表/里程碑/缓冲/回流规则同步修订），重新走 S0 评审门。
