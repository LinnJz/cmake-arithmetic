# PLAN 自检清单

## 一、编制自检（计划评审前逐项检查）

### 溯源完整性（无孤儿）
- [ ] 每个里程碑、每个任务都能 trace 回 SPEC 需求 / AC ID
- [ ] 起点推断有依据：扫描到的实际文件逐条列出
- [ ] 无编造任务——没有 SPEC 支撑的任务要么补上游，要么删

### 阶段线与门（无空转）
- [ ] 阶段表含全部适用阶段（S0-S7），跳过阶段整行标记"已跳过+依据"
- [ ] 每个阶段有进入条件与退出条件（Gate），无"待定"门
- [ ] 被起点推断跳过的阶段未留空行、未虚占责任人

### 管理视角（区别于任务清单）
- [ ] 风险与缓冲已填：至少覆盖外部依赖、人员、技术不确定性
- [ ] 外部依赖清单含交付时间与责任人
- [ ] 里程碑含缓冲天数，非零缓冲有理由

### 回流与交接（持续迭代显式化）
- [ ] 回流规则覆盖：测试失败 / AC 红 / 排期超限 / ADR 撑不住 / review 架构问题 / 依赖延期
- [ ] 交接约定已写：每 Gate 后更新 handoff.md，会话中断可续跑
- [ ] 排期超限的"PLAN 反推 PRD"路径已显式写出（可砍项清单入口）

### 可执行性（喂养执行）
- [ ] 每个任务有 coding-checklist：步骤完整、命令确切、期望输出明确
- [ ] 无"待定 / TBD / 视情况而定 / 处理好异常 / 类似前文"占位符
- [ ] 每个任务引用验证锚点（AC ID 或测试命令），无无验证的任务

## 二、阶段推进自检（每个 Gate 退出前检查）

- [ ] 已当次运行验证命令并读到输出（非先前结果、非口头转述）
- [ ] 子代理产出已独立核对（读取实际输出，非转述"已通过"）
- [ ] 退出声明附证据：命令输出 / AC 勾选 / review 结论
- [ ] 无"应该 / 大概 / 看起来"措辞
- [ ] 产出物已就位（阶段表规定的产出物文件存在）
- [ ] 若发生回流：上游文档已更新，回归测试当次重跑
- [ ] handoff.md 已更新（进度 / 未决事项 / 下一步）
